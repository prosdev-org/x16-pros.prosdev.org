What PLE is

PLE (PRos Large Executable) is the native executable format of x16-PRos.

Use PLE when the program is large, needs more than one segment, wants a splash screen or should be able to run in a GUI window.

File layout

OffsetSizeContents
0x000064 BHeader
0x00404096 BLogo, 64×64, one byte per pixel, EGA palette
0x1040n × 8 BLoad table
……Segment data, each aligned to a paragraph

Header

OffsetSizeField
0x003 BMagic 'PLE'
0x031 BFlags
0x042 BFormat version, currently 1
0x062 BEntry segment id
0x082 BEntry IP
0x0A2 BStack segment id
0x0C2 BStack SP. The loader sizes the arena from this
0x0E2 BNumber of load-table entries
0x1032 BDescription
0x3016 BAuthor

Flags

BitNameEffect
0PLE_FLAG_NO_SPLASHSkip the splash screen entirely
1PLE_FLAG_NO_WAITShow the splash but do not wait for a key

Background launches always skip the splash, whatever the flags say.

Writing one

The whole format is wrapped in programs/PLE/ple.inc, a set of NASM macros. Here is a simple program:

%include "ple.inc"

PLE_HEADER start, "Hello world program", "Author"
PLE_LOGO          "logo/hello.raw"

start:
    push cs
    pop ds

    mov ah, 0x01
    mov si, hello_msg
    int 0x21

    retf

hello_msg db 'Hello, PRos! Live long and prosper!', 10, 13, 0

PLE_END

Assemble it with:

nasm -f bin -I programs/PLE/ src/hello.asm -o HELLO.PLE

Registers on entry

RegisterHolds
CS, DSThe program's own segment 0
SS:SPThe program's stack
ESKernel data segment
SIPointer to the command line, inside ES

A program ends by returning far from its entry point with retf.

More than one segment

Segment 0 opens by itself and holds the code. Further segments are opened with PLE_SEGMENT, each up to 64 KB, so the program as a whole is not tied to 64 KB.

PLE_SEGMENT tables
big_table   times 40000 db 0

Segments sit one after another in the file and are paragraph-aligned, which means the distance from segment 0 to any other is known while assembling. PLE_SEG works it out, so there is nothing to look up at run time:

    mov ax, cs
    add ax, PLE_SEG(tables)
    mov es, ax

    ; or, in one line, clobbering AX
    PLE_LOAD_SEG es, tables
Code above 64 KB has to live in its own segment and be reached with a far call.

Stack and memory

The stack gets a segment of its own on the paragraphs just past the image, through a load table entry that carries no file bytes. The loader reads the stack pointer out of the header before it allocates anything, and asks the allocator for exactly the image plus that stack.

PLE_HEADER works the stack pointer out for you. The default is 8 KB; pass a fifth argument to ask for more:

PLE_HEADER start, "My program", "Author", 0, 16384

A program that carves up its own segment with fixed offsets should ask for PLE_FULL_SEGMENT instead, which puts the stack at the very top of segment 0 and reserves the whole 64 KB.

Do not ask for more stack than you use. The arena comes out of a 448 KB heap shared by every running program, so an oversized request costs somebody else a window.

The logo

Every PLE carries a 64×64 image in its header. The GUI reads it straight out of the file to draw the desktop icon, so there is no separate icon registry. Convert any picture with the script in the repository:

python3 scripts/img2pleimg.py my-logo.png logo/hello.raw
